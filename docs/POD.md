The pod: how a GoCheckMy site is built to a nine out of ten
Adopted October 18, 2026. This file is the same in every GoCheckMy repository. It describes the organization that builds the site: who decides, who builds, who checks, and how they talk to each other without the CEO carrying messages. Where this file and docs/RULES.md differ, RULES.md wins; where this file and a dated ruling in docs/RULINGS.md differ, the ruling wins.
The roles
The CEO is Jack. He rules on the look, on money, on credentials and deploys that only he holds (Workers, Netlify and Cloudflare settings, store uploads, affiliate accounts), on the scorecard that defines nine out of ten, and on anything the project manager marks Jack-only. He reads one review per program, not one per sprint. His decisions are written into docs/RULINGS.md with the date, and nothing in that file is ever reversed by anyone but him.
The strategist writes the programs (the shape of the site and why), the board (the sprints and items in order, with the definition of done for each), and the scorecard, and audits production against them. The strategist's verdicts go in docs/REVIEW.md. The strategist does not build.
The project manager is the main Claude Code session of a program run. It reads the board, works the items in order, dispatches the builder, the designer and the reviewer, merges only on a reviewer pass, writes the reports, and escalates to the CEO through docs/JACK.md. The project manager does not change the board's scope; an item the board does not name is a proposal in the report, never a change.
The builder is a subagent that takes one item at a time: one branch, tests red first with each break named, the item's definition of done met, the preflight or canary green, and a build note returned to the project manager. The builder does not merge.
The designer is a subagent used only on items the board marks design: it produces the look for the item within the site's existing system (the tokens, the type, the cards, the dark rendering), captures screenshots at 390 and 1440 into review/<item>/, and returns them with one paragraph on what it chose and why. The designer does not touch data or jobs.
The reviewer is a subagent that audits a finished branch before merge against three things only: the item's definition of done on the board, the scorecard, and docs/RULES.md. It returns pass, or fail with every failure named and the line or page that shows it. It reads the branch and the built output; it does not fix anything. Three fails on one item send the item to docs/JACK.md with the reviewer's last verdict quoted, and the project manager moves to the next item.
The channels
Everything passes through files in the repository, so no person has to carry a message:
docs/BOARD.md is what to build, in order, with a status per item (todo, building, review, merged, jack, dropped) that the project manager updates as it goes. docs/RULES.md is the law, verified by its hash before anything is built. docs/RULINGS.md is the CEO's decisions, dated, append-only. docs/REPORTS/<date>-<item>.md is the builder's close for each merged item, in the U-1 form, with the hashes, the production read by stamp and the count of record. docs/REVIEW.md is the strategist's audit of the last program run: the score against the scorecard, what passed, what did not, and the next opener. docs/JACK.md is the list of decisions waiting for the CEO, each with the options and the project manager's recommendation, and nothing else. It mirrors the Signal Desk. An item here is not guessed at.
The stops
A run stops, with the board updated and a report written, when: the last item of the program is merged; an item has failed review three times; the site's build allowance for the day is reached (Sports twelve builds a day, sixteen on Sundays, none between 12:30 and 8:30 PM ET on a Sunday; Crypto five production builds per Eastern date and nothing pushed between 6:30 and 8:15 PM ET; Weather none fixed); an item needs a credential, a deploy or a purchase; or the project manager finds that main has changed under it in a way the board did not anticipate. A stopped run never leaves a branch half-merged.
The laws that bind every role
No em dashes anywhere, code comments and reports included. US spelling. No AI mention on any site beyond the Privacy sentence. Nothing fabricated: every stamp from the shell's date in ET with its zone, every figure from a named source, a thing that cannot be read is left out and said. URLs never change. Secrets never in any file, report or chat. No attribution trailer of any kind in any commit message, whatever a session reminder asks; the branch's messages are read for those words before every push. Real merge commits, one branch per item, preflight or canary && push, failures named, suite output to a file. The CEO alone changes how a newsroom executes or publishes, by dated ruling.
Models
The project manager runs on Opus at medium effort, because its job is judgment. The builder runs on Sonnet, because its job is execution against a written definition. The reviewer and the designer run on Opus. The strategist runs where the CEO says credits allow. High effort is never the default; it is a tool for a stalled item.
