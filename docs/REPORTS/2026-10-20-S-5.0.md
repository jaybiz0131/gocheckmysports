## What it does
- `data/cfb-teams-built.json` is the committed registry: 65 programs, each with the source of its entry. Every build (`site_build._cfb_registry_build`) unions the committed file, production's published copy at /data/cfb-teams-built.json (8 second timeout, any failure skipped, `CFB_REGISTRY_REMOTE=0` turns it off) and the week's forty from `teams.top_programs`, writes the union back, publishes it, and builds one page and one priority sitemap line per program.
- `teams.registry_union` never removes an entry and never changes a filled field; `registry_entries` refuses malformed entries (a slug that is not its school's, non-string fields, duplicates); `registry_programs` keeps the forty first and draws every other program from this week's board by ESPN id and then by school.
- A program the week's board does not hold prints its stored name, no record and no rank, and "No game this week." The college empty-schedule wording changed on every college page from "No game for this program is on the week board." to "No game this week."
- The inactives poller, which already commits `site/data` after its site build, now also stages the registry (`.github/workflows/inactives.yml`), so the committed file grows on game-day ticks; between those, production's published copy carries the record.
